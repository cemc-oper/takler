完成触发器
==========

上一节介绍的普通触发器控制节点「能不能运行」：表达式满足时节点才被允许
运行。本节介绍**完成触发器** (complete trigger)，它控制的是节点
「要不要运行」：表达式满足时节点**直接判定为** ``complete`` ，不会
生成作业、不会提交运行。

典型场景是「这个任务的前提条件已经不成立，直接跳过」——例如某个补算
任务只在主任务失败时才需要运行，主任务一旦成功，补算任务就应该被直接
标记完成。

--------------

使用 :py:meth:`~takler.core.node.Node.add_complete_trigger` 给任意节点
添加完成触发器，表达式语法与普通触发器完全相同（见 :doc:`triggers` 与
用户指南的 :doc:`/guide/trigger-expression` ）。下面的例子中 ``t1``

与普通触发器的关系
------------------

两种触发器可以同时定义在一个节点上，但**完成触发器的检查在普通触发器
之前**：如果完成触发器满足，节点直接完成，不会再去检查普通触发器，
也不会真正运行。

因此设计工作流时要想清楚任务的「跳过条件」与「运行条件」分别是什么：
前者用完成触发器表达，后者用普通触发器表达。

.. note::

    命令行 ``show`` 的输出目前**不打印**完成触发器表达式（只打印普通
    触发器）；要确认节点是否带完成触发器，可以看 TUI 选中节点后的
    info 页（显示为 ``complete <表达式>`` ），或检查工作流定义代码。
